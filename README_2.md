# 📍 이쯤
> 어디서 모일지 고민된다면, 이쯤이에요.

"오늘 갑자기 번개인데, 어디서 만나지?"
리뷰 속 **분위기**를 분석해 우리 모임에 딱 맞는 장소를 추천해줘요.

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 이쯤 |
| 슬로건 | 어디서 모일지 고민된다면, 이쯤이에요. |
| 유형 | 미니 프로젝트 (1일 구현) |
| 목표 | 분위기 기반 추천 + 중간 지점 찾기 핵심 기능 시연 |
| 데이터 | 하드코딩된 샘플 식당 데이터 (실 크롤링은 추후 확장) |

### 1-1. 브랜드 아이덴티티

**로고**
- 지도 핀 모양 안에 물음표가 담긴 말풍선을 배치 → "어디로 갈까?"라는 질문을 형상화
- 핀이 놓인 바닥에는 동그란 리플(울림) 효과 → "이쯤!" 하고 콕 짚어주는 느낌을 표현

**브랜드 컬러**

| 용도 | 컬러명 | 코드 |
|---|---|---|
| Primary | 남색 | `#243B55` |
| Accent | 코랄 | `#F46F7B` |
| Background | 크림 | `#FFF3ED` |
| Text | 다크 그레이 | `#333333` |
| **Point/강조** | **골드** | **`#F2C14E`** |

> 💡 강조가 필요한 요소(주요 버튼, 하이라이트 태그, 포인트 아이콘 등)는 골드(`#F2C14E`)로 통일

**브랜드 키워드**: `모임` `회식` `데이트` `추천` `신뢰`

**브랜드 느낌**: 신뢰할 수 있는 AI 추천으로 우리 모임에 딱 맞는 장소를 이쯤에서
`#똑똑한추천` `#모임맛집` `#신뢰감` `#트렌디`

**브랜드 경험 흐름**

```
어디서 모일까?  →  조건 선택  →  이쯤 찾아볼게요!  →  여기쯤 어때?
(고민 시작)      (분위기,       (AI가 최적의        (우리 모임에 딱
                  음식, 지역 등)  장소 탐색)          맞는 장소 추천)
```

**활용 예시**
- 회식·팀 모임 장소 추천
- 데이트 코스 추천
- 친구·동호회 모임 장소 추천

## 2. 문제 정의 & 페르소나

**페르소나 A — 번개족 직장인**
- 갑자기 번개 모임이 잡혔는데, 근처에 모임 분위기에 맞는 맛집을 빠르게 찾고 싶다.

**페르소나 B — 회식 총무**
- 회식 장소를 골라야 하는데, 팀원들이 오기 적절한 위치에 분위기 맞는 술집 리스트를 받아보고 싶다.

**공통 페인포인트**
- 지도 앱 별점만으로는 "시끌벅적한지, 조용한지, 단체석이 있는지" 같은 **분위기 정보**를 알기 어렵다.
- 서로 다른 지역에서 모일 때 **중간 지점**을 정하는 게 번거롭다.

## 3. 주요 기능

### 3-1. 모임 컨셉 & 분위기 기반 식당 추천 ⭐ 핵심
- **시작 단계에서 오늘의 모임 컨셉 선택**: 사용자 의도를 먼저 파악하기 위한 진입 질문
  - 옵션 예: `가볍게 한잔` / `든든하게 식사` / `술 없이 맛집 탐방` / `대화 위주의 조용한 모임` / `만취 목표` / `모르겠어요`
  - 선택한 컨셉에 따라 이후 분위기 태그/음식 태그 추천 우선순위가 달라짐 (예: "만취 목표" → 술 위주, 2차 이상 태그 우선 노출 / "모르겠어요" → 전체 태그 기준 인기순 추천)
- **차수 선택**: `1차` `2차` `3차 이상` `모르겠어요`
  - 1차 → 식사 위주 식당, 2차 → 술집/포차, 3차 → 가볍게 대화하기 좋은 카페·바 등으로 추천 결과 다르게 매칭, `모르겠어요` 선택 시 차수 필터 없이 전체 노출
- 고객 리뷰를 분석해 식당별 **분위기 태그**를 유추 (예: `#조용한` `#시끌벅적` `#단체석` `#데이트` `#회식`)
- 사용자가 원하는 분위기를 선택/입력하면 태그가 매칭되는 식당 리스트 제안 (분위기 태그 목록에도 `모르겠어요` 옵션 포함, 선택 시 분위기 필터 없이 전체 노출)
- MVP에서는 리뷰 분석 결과를 **미리 하드코딩한 태그 데이터**로 시연

### 3-2. 음식 종류 & 메뉴 태그 필터
- **음식 종류 탭**: `한식` / `양식` / `일식` / `중식` / `모르겠어요` 중 선택 (`모르겠어요` 선택 시 음식 종류 필터 없이 전체 노출)
- **메뉴 태그**: 음식 종류 선택 시 하위 메뉴 태그 노출 (예: 한식 → `삼겹살` `곱창` `국밥`, 일식 → `스시` `이자카야` `라멘`)
- 분위기 태그 + 음식 종류/메뉴 태그를 **동시에 필터링**해서 추천 정확도 향상

### 3-3. 중간 지점 모임 장소 제안
- 두 지역을 입력하면 **중간 지점** 근처의 식당을 추천
- MVP에서는 지역별 좌표를 하드코딩하고, 두 좌표의 중간값과 가까운 지역의 식당을 매칭

### 3-4. 식당 상세 정보
- 전화번호, 주소, 영업시간, 대표 메뉴
- 예약 버튼 (MVP: 전화 연결 링크 `tel:` 또는 예약 페이지 링크로 대체)
- 리뷰 요약 & 분위기 태그 표시

## 4. 화면 구성 (UI Flow)

```
[메인 화면]
 ├─ 오늘의 모임 컨셉 선택 (가볍게 한잔 / 든든하게 식사 / 술 없이 맛집 탐방 / 대화 위주의 조용한 모임 / 만취 목표 / 모르겠어요)
 ├─ 몇 차인가요? (1차 / 2차 / 3차 이상 / 모르겠어요)
 ├─ 지역 입력
 │   ├─ 탭1: 한 지역 입력 → 근처 추천
 │   └─ 탭2: 두 지역 입력 → 중간 지점 추천
 ├─ 분위기 선택 (태그 버튼 다중 선택 or 직접 입력, 모르겠어요 옵션 포함)
 ├─ 음식 종류 선택 (한식/양식/일식/중식/모르겠어요 탭)
 │   └─ 메뉴 태그 선택 (선택한 음식 종류의 하위 태그)
 └─ [추천받기] 버튼
       ↓
[결과 리스트 화면]
 ├─ 식당 카드 (이름 / 분위기 태그 / 별점 / 거리)
 └─ 카드 클릭
       ↓
[상세 화면]
 ├─ 사진, 주소, 영업시간, 대표 메뉴
 ├─ 리뷰 요약 ("조용하고 대화하기 좋아요" 등)
 └─ 📞 전화하기 / 예약하기 버튼
```

## 5. 데이터 설계

### 데이터 스키마

```json
{
  "id": 1,
  "name": "골목집 포차",
  "region": "을지로",
  "lat": 37.5662,
  "lng": 126.9910,
  "moodTags": ["시끌벅적", "회식", "단체석"],
  "cuisineType": "한식",
  "menuTags": ["곱창", "전골"],
  "recommendedRound": ["1차", "2차"],
  "rating": 4.4,
  "reviewSummary": "왁자지껄한 분위기, 단체 회식으로 인기",
  "phone": "02-1234-5678",
  "reserveUrl": "https://...",
  "menu": ["곱창전골", "제육볶음"],
  "hours": "17:00 ~ 24:00"
}
```

- 분위기 태그 풀: `조용한` / `시끌벅적` / `단체석` / `회식` / `데이트` / `혼술` / `루프탑` / `감성`
- 컨셉 → 태그 매핑 (하드코딩 규칙)
  - `가볍게 한잔` → `시끌벅적` `술 위주` `2차` 태그 우선
  - `든든하게 식사` → `조용한` `1차` 태그 우선
  - `술 없이 맛집 탐방` → 음식 태그 위주, 술집 카테고리 제외
  - `대화 위주의 조용한 모임` → `조용한` `데이트` `감성` 태그 우선
  - `만취 목표` → `시끌벅적` `혼술` `2차` `3차 이상` 태그 우선, 음식보다 술집·포차 위주 노출
- 차수 태그: `1차`(식사류) `2차`(술집/포차) `3차 이상`(카페/바, 조용한 곳) `모르겠어요`(필터 없음)
- 음식 종류 & 메뉴 태그 풀
  - 한식: `삼겹살` / `곱창` / `국밥` / `찌개`
  - 양식: `파스타` / `스테이크` / `피자`
  - 일식: `스시` / `이자카야` / `라멘`
  - 중식: `짜장/짬뽕` / `마라` / `딤섬`

### 5-1. 실제 샘플 데이터 (16곳)

> 📁 실제 하드코딩 데이터는 **`data.js`** / **`data.md`** 파일로 분리 관리 (중복 방지를 위해 README에는 데이터 원본을 넣지 않음)

| 그룹 | 지역 | 개수 | id 범위 |
|---|---|---|---|

| 중간지점 검색용 (화곡 ↔ 성수) | 공덕역 인근 | 8곳 | 9~16 |

- `data.md`: 스키마 설명 + 태그 풀 + 장소별 요약표 (참고 문서)

## 8. 톤 & 카피 가이드라인

- 사용자에게 노출되는 모든 문구(안내 메시지, 결과 문구, 버튼 옆 설명, 빈 화면 안내 등)는 **"-요"체**로 통일
  - 예: "장소를 찾고 있어요", "이런 곳은 어때요?", "조건에 맞는 식당이 없어요"
- 딱딱한 "-습니다/-입니다"체는 지양, 친근하고 캐주얼한 말투 유지
- 버튼 라벨, 태그명 등 단어형 UI 요소는 예외 (완전한 문장이 아니므로 종결어미 규칙 미적용)
